# COVER_ENCODING

Cover Text 是 payload 的中文外壳，不是安全边界。它必须 100% 可逆。

## 版本

当前版本支持可选显式头：

```text
【文隐2】
```

当前默认不输出显式头，以减少明显加密标识。解码器仍支持带头和不带头两种密文。词表版本为 `coverVersion = 2`。

## 编码规则

- 每个模板 value 承载 6 bit。
- 每个模板包含若干固定槽位，槽位数量由模板定义决定。
- 每个槽位有 64 个编码值，每个编码值对应多条短语候选，承载 6 bit。
- 一个编码单元可以渲染为一个或多个中文句子，但必须作为整体被 decoder 还原。
- 每个编码单元承载 `6 + 6 * slotCount` bit。
- 最后一处不足一个编码单元时补 0，解码后通过 payload length 去除 padding。
- 当前默认使用 `compact` 长度模式，优先选择短词和高槽位模板；`balanced` 保留更强文学感。

运行时不得调用 AI 随机改写密文。

## 伪装风格

伪装风格只影响中文密文外观，不影响 payload v2 或底层加密算法。当前包含四套本地词表和模板：

- 日常风：生活记录、日记、备忘录语气。
- 聊天风：朋友闲聊、语音转文字语气。
- 小说风：场景、人物动作和氛围描写。
- 古文风：自定义仿古词表和文言句式模板，不是古籍原文摘抄。

每种风格都有独立模板、独立短语级词表、权重和禁用规则。编码时只动态加载当前选择的风格；解码时会尝试所有已发布风格模板，因此历史密文不需要额外 style 字段也能解码。

## 模板规则

模板必须语法通顺、结构固定、可解析。每个槽位必须能从编码单元中还原为 0-63 的词表索引。

封版校验要求：

- 模板渲染后必须至少包含一个 `。！？` 句末标点。
- 同一风格、同一槽位下，同一短语不能映射到多个 value。
- compact 模板必须达到密度门槛，并且样例编码单元不能解析成不同 bit 映射。
- 四种风格必须通过固定 payload 的 `encodeCoverText -> decodeCoverText` 往返测试。
